# SMC 프로토타입(MoorSMCProbe) 실측 기록

이슈: #5

## 결론 (3단계 실측 종료, 2026-11-16)

대상은 기기 한 대(MacBookAir10,1, Apple M1, macOS 13.5.2)다. 아래 "확인"은 이 기기에서 소유자가 직접 실행해 관찰한 것이고, 다른 기기나 macOS 버전에서도 같다는 뜻이 아니다.

### 확인된 것

키 값:
- `CH0B` ← `02`를 쓰면 쌍이 `02`/`02`가 되고 충전이 차단된다.
- `CH0C` ← `02`를 쓰면(`CH0B`는 `00`) 쌍이 `01`/`01`이 되고, 이때도 충전이 차단된다.
- 두 키에 차례로 `02`를 쓰면 `03`/`03`이 된다.
- 복구는 `CH0B`와 `CH0C`를 모두 `00`으로 써야 `00`/`00`이 된다.

충전 상태 반영 지연:
- 충전 상태는 키 값이 바뀐 뒤 늦게 따라온다. 차단은 38~50초, 해제는 약 42초 걸렸다.

복구 동작:
- `--revert-after` 중 SIGINT(Ctrl-C)를 받으면 복구하고 종료 코드 130으로 끝난다.
- `--revert-after` 시간이 지나면 복구한다.
- 옵션 없이 `disable-charging`을 실행하면 프로그램이 끝난 뒤에도 값이 유지된다.

#### 2026-11-16, 4차 (`CH0B`만 쓰는 `disable-charging`, 소유자 실행)

- SIGINT 복구(종료 코드 130), 시간 만료 복구를 확인했다.
- 옵션 없는 차단은 프로그램 종료 뒤에도 값이 유지됐다.
- 충전 상태 반영은 차단 38~50초, 해제 약 42초였다.
- SIGTERM, SIGHUP, 재부팅, 잠자기, `03`/`03`의 충전 상태는 실측하지 않았다.

## 가설이 코드에 반영된 범위

비트 모델(문서 맨 위 "가설")을 따르는 부분:
- `disable-charging`이 `CH0B`만 쓰는 것
- 쌍 해석 문구(`02`/`02`는 "CH0B 차단 값만 설정됨" 등)
- 테스트용 가짜 SMC(`SharedRegisterSMC`)의 동작

가설과 무관한 부분:
- 쓰기 검증은 쓴 뒤 읽힌 쌍이 기대값(`02`/`02` 또는 `00`/`00`)인지만 본다. 충전 상태는 판단하지 않고, 반영 지연을 기다리지도 않는다.

비트 모델에서 따라 나오는 해석(가설): AlDente가 만든 `02`/`02`는 `CH0B`에만 `02`를 쓴 결과이고, 2026-11-15에 본 `01`/`01`은 `CH0C` 쪽만 켜진 상태다.

반영 지연 때문에 주의할 점: `--revert-after`나 `--hold`가 40~50초보다 짧으면 충전이 멈추기 전에 복구되어 `pmset -g batt`에 변화가 보이지 않을 수 있다.
